## 观察

- `web/scripts/test-focus-visible.mjs:446` — `(css.match(/data-theme='light'|…/) || []).length >= 0` 是恒真表达式，「亮色也有（成对出现）」这条断言**永远通过**，等于零覆盖，而它本该守的是「深/亮 `--el-*` 成对」。
- `web/scripts/test-focus-visible.mjs:69-78` — `hasFocusVisible` / `hasFocusWithinRing` 是**整文件布尔**，只要文件里任意一处 `:focus-visible`，所有 `outline:none` 规则都被判为「已有补偿」，不校验选择器是否对应；真删掉 `.form-textarea:focus-visible` 仍可能全绿——这正是 :30 想防的那类假绿，只是换了个层级。
- `web/scripts/test-focus-visible.mjs:33` — `templateOf` 用贪婪 `([\s\S]*)` 取到**最后一个** `</template>`；任何在 `<script>` 之后还出现 `<template>` 字样的注释/示例都会把尾部混进「模板」，使 :3322、:3349 这两处防注释假绿的检查本身不可靠。
- `web/scripts/test-focus-visible.mjs:1342` — `ok(..., /groupBy 只加在数据查询/.test(art))` 匹配的是**注释文字本身**；删掉真正的 `groupBy` 不会失败，改一句注释反而会红。断言即文档，等于没测代码。
- `web/scripts/test-focus-visible.mjs:519-520` 与 `:2530` — 同类问题：断言「代码里不再出现『目前没有接入 admin』」「注释里必须有『缓存失效已接入 admin』」「留了『不要加 `Disallow: /#/`』说明」。把注释措辞当契约，与它自己在 :505-508 记的教训（过期注释会让人去修不存在的缺陷）正面冲突。
- `web/scripts/test-focus-visible.mjs:1916` — `/\$\{selection\.value\.length\}|count/` 的 `count` 分支过宽，`article_count`、`commentCount` 都会命中，「五个批量删除入口必须报数量」在多数页面形同虚设。
- `web/scripts/test-focus-visible.mjs:2520` — `allowCount === 2` 是精确等值；将来加第三个域（如后台域 robots）就红。把「当前部署拓扑」写死成断言，属脆弱断言。
- `web/scripts/test-focus-visible.mjs:1512-1522` 与 `:3033-3053` — `CommentItem.likeComment` 被两段几乎逐条重复断言（`liked || liking` 门闩、回滚、`xalor_clike_`），实现微调要改两地；且 :3045 用 `includes('Math.max(0, (props.comment.likes || 1) - 1)')` 把回滚表达式钉成字面量，正常重构即红。
- `web/scripts/test-focus-visible.mjs:19-24`（配合 :369、:512、:535 等） — `read()` 是裸 `readFileSync` 且大量跨包读 `../../server/...`，没有任何存在性守卫；`server/` 未 `npm i` 或某路由改名会让 3510 行套件直接抛栈退出，看不出是哪一条失败。
- `web/scripts/test-focus-visible.mjs:3509-3510` — `console.log` 后紧接 `process.exit()`，stdout 被重定向到管道/文件时末尾汇总行可能丢失；且退出码只有 0/1，无「跳过」「部分通过」语义，CI 无法区分「代码坏了」与「文件找不到」。
- `web/scripts/test-focus-visible.mjs:1658-1665` — Ctrl/Cmd+K 的三条断言各自在**文件任意位置**匹配，不保证 `e.ctrlKey || e.metaKey`、`e.key === 'k'`、`openSearch()` 在同一个处理器内；把处理器拆成两半（一半失效）仍全绿。
- `web/scripts/test-focus-visible.mjs:3505` — `!/^input:focus\s*\{/m` 只挡行首写法，`.form-input:focus {`、`input:focus,` 换行等变体不会被发现；「鼠标点击不被焦点环打扰」实际只覆盖一种排版。
- `web/scripts/test-focus-visible.mjs:2884`（同类 :540、:1967、:2740） — 用「出现次数 ≤2 / 顶层字段 ≤12 / `withTitle >= 10` / `titles >= paths - 1`」这类阈值兜底，新增第三处 `scrollHeight` 或减到 9 个带 meta 的路由都不会失败，阈值本身成了容错窗口。
- `web/scripts/test-focus-visible.mjs:1-18` — 文件名与注释都只讲「键盘焦点可见性」，实际 145 个分区覆盖 SEO、后端安全、性能、本地存储；若 `package.json` 按名字挂 `test:focus-visible` 门禁，新增领域没有归属地，也不会有人想到来这里改。

## 小结

1. 它是这个仓库的**唯一一道跨前后端静态门禁**：不跑浏览器、不连库，纯 `readFileSync` + 正则，用 `pass/fail` 计数与 `process.exit` 给出 CI 可用的布尔结论，成本和覆盖率之比极高。
2. 内容重心早已从「focus-visible」漂移到「**用户可感知的失败模式**」——翻页被 watcher 冲掉、加载中无播报、保存后误报未保存、被引用的图片能删、CSV 公式注入、`Vary: Host` 缺失导致分享卡片串域。每条注释都带着「实测数据 + 我踩过的坑」，是仓库里最厚的口头工程记忆。
3. 边界很硬：它只证明**源码文本里有这些写法**，不证明运行时真的生效。大量条目依赖注释自述（:1342、:519-520）与脆弱阈值（:2884、:2520、:2740），一旦破窗就会变成「看起来有覆盖」。
4. 与后端的耦合是**路径级**而非契约级：`server/src/routes/*.js` 一旦改名或拆分，整个套件 crash 而不是局部失败，这是当前最大的可用性风险。
5. 它的自省质量高于平均：:26-31、:505-508、:2654-2682、:3311-3321 都记录了「我上次断言写错了」的具体形状，并据此改成不钉实现细节的断言（如 :3427-3442 只钉「四个处理器都在链上」）。这类自我修正应继续作为新增断言的模板。
